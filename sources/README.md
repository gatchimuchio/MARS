# 原典保全・突合（史料が正本、分析は派生物）

**原典の本文・図表は分析レポートより上位の証拠である。** 検証者は解釈に疑問があれば必ず原資料へ戻れる必要がある。研究者の要約だけを資料の正本として保全してはならない。

| 対象 | 保存先 | 公開GitHubへの登録 | 位置づけ |

| 原資料の発行者・正式URL | [`docs/SOURCE_REGISTER.md`](../docs/SOURCE_REGISTER.md) | する | 原文の公開場所への直接参照 |

## 原資料をそのまま取得

標準Pythonのみで動作。登録簿 S01–S35 にある公開原資料の本文をそれぞれ取得し、SHA-256アドレスのファイルとして**バイト単位で保管**する。自動要約・OCR・翻訳は保存時に行わない。

```bash
# 原典の一覧を調べる
python3 tools/archive_originals.py list

# 登録済み公開資料をすべて保存。URLへの外部アクセスが必要
python3 tools/archive_originals.py fetch --all

# 一件のみを保存する場合
python3 tools/archive_originals.py fetch --id S14

# 取得済み資料が当時の取得内容と同一か照合
python3 tools/archive_originals.py verify
```

プログラムはリポジトリ直下で実行する。原ファイルは `.gitignore` により公開Gitから除外。実際の原文を開く場合は `originals.lock.json` の該当IDの `local_object` を `sources/_local_originals/` に続ける。たとえば S14 はそのパスのPDFをPDFビューアで開き、[突合索引](../docs/research/EVIDENCE_CROSSWALK_2026-11-09.md) に指定されたページと照合する。

## 版の扱い

- `originals.lock.json` には **取得したファイルのSHA-256とバイト長**を記録する。URLの存在や公開年だけをもって同一内容とみなさない。
- 発行者が同じURLの文献を差し替えた場合、新しいSHAの原典を**追加**し、既存の取得履歴は上書きしない。
- `verify` は、原典本体と取得履歴の両方が存在する環境で実施する。GitHubをクローンした直後は原典本体がないため、`fetch` が必要。
- `originals.lock.json` に記録したSHAの原典が公式URLで取得できなくなった場合、**当時の原文を再取得できたと主張しない**。古いローカルコピーの存在・権利者の許諾・別の正規公開先を調査する。
- 文字抽出や注釈の誤りは原PDFと独立に訂正する。原文のOCR結果を原本の完全な複製と扱わない。

## 権利境界と保全限界

- 日立評論は自サイトの文章・図表・写真の著作権者を明示し、情報処理学会は無断転載・複製・公衆送信を原則認めず、転載許可の申請手段を公開している。
- **公開ウェブで読めることは、別の公開GitHubで全文再配布できる許可を意味しない。** 本リポジトリは原典そのものの著作権・再配布許諾を取得していないため、第三者の原PDF・HTMLをGitHubに同梱しない。
- ローカルへの取得・保存も、用途や利用条件に応じて適法性を確認する。第三者へのファイル配布・外部公開を目的としたアーカイブではない。
- 将来権利者から再配布許諾を得た場合、**許諾の主体・対象資料・版・範囲・条件を記録したうえで**同梱方法を再決定する。
