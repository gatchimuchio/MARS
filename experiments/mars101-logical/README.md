# MARS-101 論理再現実験 / Logical Reconstruction Lab

日本国有鉄道・日立製作所が1964年に公表した **MARS-101 の設計思想の一部**を、架空データを用いて実行・監査する小規模実験。

**これは実物の MARS-101 ソースコード、HITAC-3030 の命令体系、MARS 505、JR の業務用システムの再現ではない。** 原設計に対する対応関係と、未確認部分を区別するための基準実験である。JR各社・JRシステム・日立製作所とは無関係。実際の座席予約、乗車券発行・決済は行わない。

## 実装済みの一本通し

1. 架空の端局要求を受信する（要求入力を模擬）。
2. TC 相当処理で列車・乗降駅を区間番号に変換する。
3. FC 相当処理で、区間ごとの占有ビットパターンを重ね合わせて空席を検索する。
4. 複数席を選び、対象となるすべての区間を一回の予約操作として更新する。
5. 独立した **A/B 二系統**で同じ処理を計算し、結果と在庫状態を照合する。
6. 一致した場合だけ、状態と処理記録を一緒に永続化する。
7. 予約番号と **実券ではない**実験用の発券情報を返す。
8. 別の操作で、取消・再使用・履歴再生監査を実行できる。

### 実行

外部ライブラリ不要。**Python は検証用ホスト処理系**であり、原機の採用言語だと主張するものではない。原機の言語・命令セットは、原資料の調査が完了するまで未確定として保持する。

```bash
python3 mars101_lab.py demo
python3 -m unittest discover -s tests -v
```

状態を残して対話操作する例：

```bash
python3 mars101_lab.py init --state lab-state.json
python3 mars101_lab.py inquire --state lab-state.json --from A --to C
python3 mars101_lab.py reserve --state lab-state.json --from A --to C --count 2
python3 mars101_lab.py history --state lab-state.json
python3 mars101_lab.py audit --state lab-state.json
```

実験用の列車 `TEST-101` は A→B→C→D の4駅、合計6席。料金は架空の1区間100単位。確認・予約・取消で使う `--request-id` を明示して再送した場合、同一内容は重複販売せず前回の結果を返す。

## 主張できる再現範囲

| MARS-101 公開資料の構成・原理 | 実験で対応するもの | 境界 |
|---|---|---|
| TRC → SC → TC → FC → SC → TRC | 要求入力→オーケストレーション→テーブル参照→在庫操作→結果 | 通信プロトコルは未再現 |
| 座席ファイルは区間ごとの占有ビット表現 | `occupancy[区間]` の整数ビットマップ | 実機のドラム配置・命令コードは未再現 |
| 要求区間にわたるパターン重合 | 区間間のビット OR による使用中席の集合 | 厳密な機械語命令列は未確認 |
| 二系統独立処理、最終段の照合 | 二系統の結果・全在庫ダイジェスト照合 | 原機の故障時切替手順は未再現 |
| 要求・回答記録と復旧用保存 | 永続化されたイベント列と全数再生監査 | 磁気テープ形式・時刻別バックアップは未再現 |
| 自動発券 | 実験用の発券情報 | 実物の料金表・符号・印字方式は未再現 |

## 実験の安全条件と監査

- 同一列車・同一区間・同一座席の重複予約を許さない。
- 同一区間の一部しか空いていない席を、全区間予約の候補にしない。
- A/B 二系統が一致しなければ、記録・発券・在庫の変更を確定しない。**二系統不一致だけで正しい側を決められるとは主張しない**。
- 要求と回答は一つのイベントとしてハッシュ連鎖に記録する。起動後は履歴を再実行して保存状態と照合できる。
- 単一プロセスの複数スレッドや複数端局プロセスによる同時入力は、実験用の単一書込ロックで安全側に直列化する。歴史的 MARS-101 の並列化性能を再現しているわけではない。
- 永続化は小規模実験のため全状態JSONの原子的置換を使う。実機のファイル更新・記録の方式とは異なる。
- データ破損・照合不一致ではエラー停止し、推測による自動復旧を行わない。

## 未確認・非再現項目

- HITAC-3030 のプログラム表現、原機で使用した正確な言語、アセンブラ、命令体系。
- 端局装置の 20 / 26 レター通信の各符号割当・パリティ処理・50ボーの時系列。
- 座席割当の車両優先順位と利用効率アルゴリズム。現時点は **暫定的な座席順 first-fit**。
- 原機の高優先度割込み、Master Priority Control、TC/FC の待ち行列・独立並列実行。
- 磁気ドラム、テープ、印刷機、二系統故障復帰のタイミング。
- 実在の運賃計算、特殊な営業制度、原機の外部インターフェース。

これらを再現済みとすることは、同一性の過大主張になる。次段階では当時のハードウェア資料・端局符号表・操作プログラム・試験記録を整理し、**原機の機構と検証用ホスト言語を分離したまま**再現度を上げる。
