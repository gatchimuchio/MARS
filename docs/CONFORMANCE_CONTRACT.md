# 言語非依存の論理実験契約（C-001）

## 適用範囲

これは各プログラミング言語に対する**共通テスト用の人工的仕様**であり、1964年のMARS-101正式仕様・通信規格ではない。どの言語にとっても同じ評価対象を作るための最小条件である。

## 状態

架空列車 `TEST-101`、駅 `A→B→C→D`、座席 `1-01,1-02,1-03,1-04,2-01,2-02`、区間料金100単位。座席は車両・番号の昇順とする。座席割当規則は史料上の優先順位が未確定のため **実験専用 first-fit**。

各区間 `k` に対して座席占有ビット集合 `B[k]` を保持する。要求区間 `[i,j)` の使用中席は `U = OR(B[i],…,B[j-1])`。要求区間全体の空席は `(~U) & ((1<<N)-1)`。

### 入力

```json
{"request_id":"r-1","op":"RESERVE","train":"TEST-101","from":"A","to":"C","count":2}
```

`op` は `INQUIRE` / `RESERVE` / `CANCEL`。取消は `reservation` を指定する。`request_id` は非空文字列。同じID・同じ内容の再送は、処理を繰り返さず元の結果を返す。異なる内容でのID再利用は拒否する。

### 出力・状態遷移

1. `INQUIRE`：空席数を返す。在庫変更なし。ただし要求・回答は履歴に記録する。
2. `RESERVE`：指定区間を通じて共通する空席が `count` 席以上なら、その先頭の席を選び、各区間の占有ビットを更新。料金は `区間数×100×人数`。不足なら `SOLD_OUT`、在庫変更なし。
3. `CANCEL`：存在する有効予約の占有区間だけ解除。存在しなければ `NOT_FOUND`、在庫変更なし。解除済み予約の重複取消は `NOT_FOUND`。
4. 成功時の予約番号は `L` とイベント通番6桁の合成値（例：初回照会の後の予約は `L000002`）。
5. どの正常処理でも、A/Bレーンの出力と最終状態を照合してから結果を確定する。不一致時はコミットせず停止する。
6. 履歴を先頭から再生し、記録された応答と最終在庫が一致することを監査できる。

## 観測可能な合格条件

- 初期のA→C照会：6席。
- A→Cを2席予約：`1-01, 1-02` が割り当てられ、料金は400単位。
- 続くA→C照会：4席。
- A→Bの予約後、同じ席をB→Cに再販売可能。ただしA→Cの通し予約には使えない。
- 取消した予約の区間だけ復旧し、他予約の区間は保持する。
- 9件以上の同時要求でも、6席を超えて予約成立しない。
- A/Bの意図的な不一致、無効な入力、破損した記録に対して安全側に停止する。
- 再実行・再起動後も同じ結果となる。

実装ごとに同等の入力・出力・状態・失敗条件が成立すればC-001適合。**これは原機適合を意味しない**。端局コード・機械語命令・実際の料金規則を得た後、歴史的適合試験は別の契約番号で定義する。
