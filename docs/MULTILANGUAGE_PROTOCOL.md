# 多言語比較実験プロトコル（L-001）

## 目的

特定言語の優位性の宣伝ではなく、**同一の工学的成立条件に対して言語・処理系がどのような制約・費用・差異を生むか**を観測する。歴史的な原機の復元と混ぜない。

## 言語採用と実験の順序

1. `docs/CONFORMANCE_CONTRACT.md` の検証仕様を固定する。
2. 対象とする言語・処理系・コンパイラ・最適化設定・OS・CPUを記録する。
3. 機能全体を通す実装を先に成立させる。
4. 同じ入力と失敗条件で全数の適合試験を実行する。**不適合は性能比較から分離して記録**する。
5. 合格した実装だけで、計測対象の仕事量・時間・メモリ・I/O・回復挙動を比較する。
6. 原因を言語そのもの・コンパイラ・標準ライブラリ・実行環境・個別の実装判断へ切り分ける。

候補言語は実験目的から決定する。COBOL、C、C++、Rust、Go、Java、Ada、Python、Zig 等は**候補例であり採用確定ではない**。実験のために言語を恣意的に限定した場合も、限定条件を明示する。

## 公平性の条件

| 項目 | 保持条件 |
|---|---|
| 目的・機能 | C-001の入力、出力、状態、成功・拒否条件を固定 |
| アルゴリズム | 区間ビットマップ、空席選択順、取消、ID再送、二系統照合という基準を保持 |
| 性能実験 | 同一データセット、同じ同時要求数、同じ計測区間、同じCPU・メモリ制限 |
| ビルド | コンパイラ名・バージョン・最適化・実行コマンドを記録 |
| 環境 | OS・ランタイム・CPU・記憶装置・ネットワーク等を記録 |
| 測定 | 事前ウォームアップ・測定回数・分散・失敗数・測定時ログを記録 |
| 観測 | 応答時間の平均だけでなくp95/p99、スループット、資源、拒否・復旧状態を確認 |
| 説明可能性 | 「言語が速い」と「その実装／処理系が速い」を区別 |

各言語を一人の実装者が書いたことに起因する実装差も交絡要因となる。可能なら言語ごとに複数の独立実装、複数コンパイラ・実行条件で再測定する。

## 試験群

1. **正当性**：区間の重なり・複数席・取消・ID再送・再起動・履歴復元。
2. **競合**：同じ席を狙う要求を同時投入しても二重販売しない。
3. **障害**：処理中の停止、二系統不一致、記録破損、途中失敗時のコミット境界。
4. **負荷**：低負荷・持続高負荷・短時間集中のそれぞれで遅延・資源・復旧を測定。
5. **変更容易性**：同一の仕様変更に必要な変更箇所・テストの影響・欠陥混入を記録。

## 公表時の表現

- 合格実験数と成立条件を合わせて表示する。局所的な高速化を全体の優位性に変換しない。
- 再現不能な結果、未測定項目、途中停止、異常値も削除せず記録する。
- 性能値に「再現実験の人工的負荷」という対象境界を明示し、実際のMARSの性能と比較同一視しない。
- 実際のJRに対する負荷・ネットワーク試験は行わない。
